# Decision Journal — Technical Spec

## How This Works, In Plain Language

Decision Journal은 **브라우저 안에서만 돌아가는 웹 페이지 하나**다. 서버도, 로그인도, 설치도 없다.

- **HTML**(`index.html`)은 화면의 뼈대다. 상단 탭, 목록, 입력 폼, 분석 화면이 들어갈 자리를 만든다.
- **CSS**(`css/styles.css`)는 꾸밈이다. 오프화이트 배경, 둥근 흰 카드, 절제된 빨간 경고, Insights의 막대그래프 모양을 정한다.
- **JavaScript**(`js/` 폴더)는 동작이다. 역할별로 파일을 나눴다.
  - `strings.js` — 화면에 보이는 **모든 한국어 문구**를 모아 둔 사전. 영어로 바꿀 때 이 파일만 고친다.
  - `calc.js` — **계산만 하는 부분**. 자신감 구간 나누기, 적중률(맞음 1 · 일부 맞음 0.5 · 틀림 0), Reality Check 판정, Insights 수치, 기록 상태(검토 예정 / 검토할 때 됨 / 결과 기록 완료)를 계산한다. 화면이나 저장소를 건드리지 않기 때문에 따로 떼어 테스트하기 쉽다.
  - `storage.js` — **localStorage에 읽고 쓰는 부분**. localStorage는 브라우저가 이 사이트 전용으로 보관해 주는 메모장이다. 기록 전체를 하나의 묶음으로 저장하고, 앱을 열면 다시 읽어 온다. 예측은 잠그고 결과만 바꾸는 규칙도 여기서 지킨다.
  - `sample-data.js` — 처음 열 때와 `샘플로 초기화` 때 넣을 **가상 샘플 10개**를 만든다.
  - `app.js` — 화면을 그리고 버튼·슬라이더·필터 같은 사용자 동작에 반응한다. 위의 파일들을 불러 쓰는 "지휘자"다.

화면 이동은 주소 끝의 `#` 뒷부분(예: `#insights`)으로 구분한다. 페이지 전체를 새로 불러오지 않고 같은 페이지 안에서 보여 줄 부분만 바꾼다. 그래서 새로고침해도 보던 화면에 그대로 머문다.

**왜 이 모양인가:** 화면 4개짜리 1인용 앱에 서버와 로그인이 없다는 조건이 있다. React 같은 프레임워크나 빌드 도구는 이 규모에서 얻는 것보다 설치·실행 단계가 더 늘어난다. 계산(`calc.js`)과 저장(`storage.js`)을 화면 코드와 분리해 두면, 핵심 규칙이 제대로 동작하는지 자동 테스트로 확인할 수 있다.

## The Core Journey Through the System
PRD ref: `prd.md > The Core Journey`.

1. **앱을 연다** → `app.js`가 `storage.js`에 저장된 기록을 요청한다. 저장된 게 없으면 `sample-data.js`가 오늘 날짜 기준으로 샘플 10개를 만들어 저장한다. 그다음 `calc.js`가 각 기록의 상태를 계산하고, Journal 목록과 샘플 데이터 안내가 그려진다.
2. **New decision을 누른다** → 주소가 `#new`로 바뀌고 입력 폼과 오른쪽 Reality Check 패널이 그려진다.
3. **자신감 슬라이더를 80으로 움직인다** → 움직일 때마다 `calc.js`의 Reality Check 함수가 결과가 기록된 기록 중 80–89% 구간만 골라 적중률을 계산한다(샘플 기준 4개, 50%). 차이가 30%p로 15%p 이상이므로 패널이 빨간 경고 문구로 바뀐다. 슬라이더 값 자체는 건드리지 않는다.
4. **저장한다** → `storage.js`가 새 기록을 `review: null`(아직 결과 없음)로 저장한다. 결과가 없으니 이후 계산에서는 빠진다. Journal 목록으로 돌아가면 새 기록이 `검토 예정`으로 보인다.
5. **새 기록을 연다** → `#decision/<id>` 상세 화면에서 예측 내용이 글자로만 보이고, 입력란은 없다.
6. **`검토할 때 됨` 샘플을 열어 결과를 기록한다** → `storage.js`가 그 기록의 `review` 부분만 저장한다. 이제 이 기록은 80–89% 구간 계산에 포함된다(5개, 60%).
7. **Insights 탭을 연다** → `calc.js`가 결과 기록 완료 기록으로 요약 수치와 구간별 막대를 다시 계산한다. 80–89% 구간이 4개 → 5개, 50% → 60%로 바뀐 것이 보인다.

## Stack

- **HTML, CSS, JavaScript (프레임워크 없음, 빌드 없음).** 학습자가 선택했다. 이유: 설치 없이 실행되고, 기능이 제대로 작동하는지에 집중할 수 있다. 감수한 점: 화면 갱신을 직접 코드로 챙겨야 한다.
  문서: [MDN HTML](https://developer.mozilla.org/ko/docs/Web/HTML), [MDN CSS](https://developer.mozilla.org/ko/docs/Web/CSS), [MDN JavaScript](https://developer.mozilla.org/ko/docs/Web/JavaScript)
- **localStorage** — 학습자가 정한 저장 방식. 문서: [MDN Window.localStorage](https://developer.mozilla.org/ko/docs/Web/API/Window/localStorage)
- **스크립트 불러오기 방식:** JavaScript 파일을 일반 `<script>` 태그로 순서대로 불러온다. 각 파일은 자기 기능을 `window.DJ`라는 공용 보관함에 올려 두고, 다음 파일이 꺼내 쓴다. 더 현대적인 "모듈" 방식은 `index.html`을 더블클릭해 열면 브라우저 보안 규칙 때문에 동작하지 않아서 쓰지 않는다. 같은 파일을 Node.js(아래 테스트 도구)에서도 불러올 수 있게, 파일 끝에서 Node용 내보내기도 함께 한다.
- **테스트 도구 (개발용, 앱 실행에는 불필요)**
  - **Node.js 내장 테스트** (`node --test`) — 계산 규칙 검사. 추가 설치가 없다. 문서: [Node.js test runner](https://nodejs.org/api/test.html). 이 환경은 Node 22다.
  - **Playwright** — 실제 브라우저(Chromium)를 코드로 조종해 화면을 누르고, 새로고침하고, 결과를 확인하는 도구. 새로고침 후 기록 유지 테스트에 쓴다. 문서: [Playwright Library](https://playwright.dev/docs/library). 버전은 이 환경에 설치된 브라우저와 맞는 `1.56.1`로 고정한다.

## Where It Runs and How Someone Tries It

**런타임:** 최신 데스크톱 브라우저(Chrome, Edge, Firefox, Safari). API 키 없음.

**1) 내 컴퓨터에서:** 저장소를 내려받아 `index.html`을 더블클릭한다. 앱 실행에는 설치가 필요 없다.

**2) Claude Code 웹 환경에서 미리보기 (빌드 중 주 확인 방법)**
- **Artifact 미리보기:** 빌드 단계마다 `index.html`과 `css/`, `js/` 파일을 비공개 claude.ai Artifact로 올린다. Artifact는 Claude가 올려 주는 개인용 웹 페이지이고, 기본적으로 학습자만 볼 수 있다. 학습자는 받은 링크를 자기 브라우저에서 열어 직접 눌러 보고 새로고침해 볼 수 있다. Artifact마다 저장 공간이 따로 있어서 localStorage도 링크별로 유지된다. 같은 링크로 다시 올리면 최신 버전으로 바뀐다.
- **스크린샷:** 이 컨테이너 안의 Chromium으로 각 화면을 찍어 대화에 보여 준다. Playwright 테스트도 같은 브라우저로 돌린다.
- 컨테이너 안의 `localhost` 주소는 학습자 브라우저에서 열 수 없다. 그래서 학습자가 직접 확인하는 경로는 Artifact 링크다.

**3) 데모 영상 녹화**
- Artifact 링크(또는 내려받은 `index.html`)를 데스크톱 브라우저에서 열고 화면을 녹화한다. macOS는 `Cmd+Shift+5`, Windows는 캡처 도구의 녹화 기능을 쓴다.
- 녹화 전에 `샘플로 초기화`를 눌러 깨끗한 샘플 상태에서 시작한다. 그래야 80–89% 구간의 "4개 → 5개" 변화가 계획대로 보인다.
- 시연 순서는 `prd.md > The Core Journey` 1–7을 따른다. 3단계에서 슬라이더를 **80**에 놓는다.

**제출 요건:** 짧은 데모 영상과 공개 GitHub 저장소가 둘 다 필요하다. 배포(공개 URL)는 선택이고 영상을 대신하지 않는다. 원하면 `6-ship`에서 GitHub Pages(저장소 파일을 그대로 웹사이트로 올려 주는 무료 기능)를 고려한다. 빌드 과정이 없는 앱이라 설정이 간단하다.

**개발자 명령 (이 환경과 내 컴퓨터 공통):**
- `npm test` — 계산 규칙 테스트 (설치 불필요)
- `npm install` 후 `npm run test:e2e` — 브라우저 테스트 (Playwright 필요)

## Components

### Strings (`js/strings.js`)
화면 문구 사전. 탭·버튼·필터·상태·분야·기분·검토 기간 이름, 안내·경고·확인 문구가 모두 여기 있다. 숫자가 들어가는 문구는 값을 넣어 문장을 만드는 작은 함수로 둔다. 예: `realityWarning(80, 5, 60)` → "현재 자신감은 80%지만, 과거 비슷한 자신감으로 예상한 기록 5개의 실제 적중률은 60%였어요". 다른 파일에는 한국어 문장을 직접 쓰지 않는다.
PRD ref: `prd.md > Look and Feel`.

### Calculations (`js/calc.js`)
화면과 저장소를 건드리지 않고 계산만 한다. 같은 입력이면 항상 같은 결과를 낸다.
- `bandOf(confidence)` → 구간 시작값. `Math.floor(c / 10) * 10`이고, 100은 90으로 처리한다(90–100 구간).
- `scoreOf(accuracy)` → 맞음 1, 일부 맞음 0.5, 틀림 0.
- `hitRate(decisions)` → 점수 합 ÷ 개수 × 100. 개수가 0이면 숫자 대신 "없음"(`null`)을 돌려준다.
- `realityCheck(confidence, decisions)` → 같은 구간에서 결과가 기록된 기록만 모아 `{ kind: 'insufficient' | 'warning' | 'similar', count, hitRate, includesSample }`를 돌려준다. 3개 미만이면 insufficient, |자신감 − 적중률| ≥ 15이면 warning, 그 외는 similar.
- `insights(decisions)` → 요약(완료 수, 전체 적중률, 평균 자신감, 차이)과 구간별 목록 `{ band, count, avgConfidence, hitRate, verdict }`. verdict는 Reality Check와 같은 3개·15%p 기준으로 정한다. 평균 자신감 > 적중률이면 과신, < 이면 과소확신.
- `statusOf(decision, today)` → 검토 예정 / 검토할 때 됨 / 결과 기록 완료.
- **반올림 규칙:** 경고·판정과 15%p 비교는 반올림하지 않은 값으로 한다. 화면에는 정수로 반올림해 보여 준다(예: 83.3 → 83%). 화면에 보이는 "차이"는 반올림된 두 숫자끼리 뺀 값이다(`displayGap(a, b) = round(a) − round(b)`). 그래서 드물게 화면 차이가 15인데 "비슷함"이거나, 14인데 경고인 경우가 생길 수 있다(예: 80 vs 65.4 → 화면 차이 15, 실제 14.6 → 비슷함). 학습자가 이 방식을 선택했다.
PRD ref: `prd.md > Reality Check`, `prd.md > Insights`, `prd.md > Journal List`.

### Storage (`js/storage.js`)
localStorage 키 `decision-journal.v1` 하나에 전체 데이터를 JSON(글자로 된 데이터 묶음)으로 저장한다.
- `load()` — 저장된 데이터를 읽는다. 없으면 샘플을 만들어 저장한 뒤 돌려준다.
- `addDecision(fields)` — 새 기록을 만든다. id와 기록 날짜는 여기서 정하고, `isSample: false`, `review: null`로 둔다.
- `saveReview(id, review)` — 해당 기록의 `review`만 바꾼다. 예측 쪽 값이 함께 넘어와도 무시한다. **잠금 규칙의 실제 보호 장치.** 처음 기록이면 `reviewedAt`, 수정이면 `editedAt`을 남긴다.
- `resetToSamples()` — 저장 데이터를 오늘 기준 새 샘플로 통째로 바꾼다. 확인창은 `app.js`가 띄운다.
- 저장할 때마다 전체를 다시 쓴다. 10여 개 기록이라 충분히 빠르다.
PRD ref: `prd.md > Sample Data and Reset`, `prd.md > Locked Prediction and Outcome Review`, `prd.md > States and Boundaries`.

### Sample Data (`js/sample-data.js`)
`buildSamples(today)`가 아래 **Sample Data Plan**의 10개 기록을 오늘 날짜 기준으로 만든다. 모든 기록에 `isSample: true`가 붙는다. 이름·장소·회사 등은 전부 가상이고 학습자의 개인 정보는 없다.
PRD ref: `prd.md > Sample Data and Reset`.

### App Shell and Navigation (`index.html`, `js/app.js`)
공통 상단(앱 이름 Decision Journal, Journal / Insights 탭, New decision 버튼, 샘플 데이터 안내)을 그린다. 주소의 `#` 부분을 보고 해당 화면 하나만 그린다: `#journal`(기본), `#new`, `#decision/<id>`, `#insights`. 없는 id를 열면 Journal로 돌려보내고 "기록을 찾을 수 없어요"를 보여 준다.
PRD ref: `prd.md > Screens and Layout`.

### Journal List View (`js/app.js`)
상태 필터(전체 / 미해결 / 완료)와 분야 필터를 함께 적용해 카드를 그린다. 미해결은 검토 예정과 검토할 때 됨을 함께 포함한다. 정렬은 기록 날짜 최신순이다. 필터 선택은 화면에서만 유지하고 저장하지 않는다. 결과가 없으면 "조건에 맞는 기록이 없어요"를 보여 준다. 목록 아래에 `샘플로 초기화` 버튼이 있고, 브라우저 기본 확인창으로 PRD 문구를 띄운다. 취소하면 아무것도 하지 않는다.
PRD ref: `prd.md > Journal List`, `prd.md > Sample Data and Reset`.

### New Decision Form and Reality Check Panel (`js/app.js`)
- 폼 항목은 PRD와 같다. 자신감 슬라이더는 0–100, 1 단위이고, 시작값은 50이다(구현상 정한 값). 현재 값을 슬라이더 옆에 숫자로 보여 준다.
- 슬라이더의 `input` 이벤트(움직이는 동안 계속 발생하는 신호)마다 `calc.realityCheck`를 불러 오른쪽 패널을 다시 그린다.
- 패널은 항상 비교 기록 수와, 샘플이 포함되면 `샘플 데이터 포함`을 보여 준다. warning과 similar일 때는 현재 자신감과 과거 적중률도 보여 준다. insufficient일 때는 부족 문구와 개수만 보여 준다.
- 저장할 때 이유를 뺀 필수 항목이 비어 있으면 저장하지 않고, 빈 항목 옆에 안내를 띄운다.
PRD ref: `prd.md > New Decision Form`, `prd.md > Reality Check`.

### Decision Detail and Review View (`js/app.js`)
- 예측 영역에는 결정, 예상 결과, 이유, 분야, 기분, 자신감, 검토 기간, 기록 날짜, 검토 예정일을 **글자로만** 표시하고 "저장 후 잠긴 예측이에요"를 적는다. 입력란과 편집 버튼은 없다.
- 결과가 없으면 결과 입력 영역(실제로 일어난 일, 예측 적중 3택, 결과 평가 3택)이 보인다. 두 평가는 별도 질문으로 나눈다. 검토 예정일 전에도 입력할 수 있다.
- 결과가 있으면 결과를 글자로 보여 주고 `결과 수정` 버튼을 둔다. 누르면 같은 입력 영역이 기존 값이 채워진 채 열리고, 저장 또는 취소할 수 있다.
- 세 항목이 다 있어야 저장된다. 저장은 항상 `storage.saveReview`로만 한다.
PRD ref: `prd.md > Locked Prediction and Outcome Review`.

### Insights View (`js/app.js`)
`calc.insights` 결과로 상단 요약 4개와 구간별 그래프를 그린다. 그래프에는 결과 기록이 1개 이상인 구간만 보인다(PRD Open Question: 기록이 있는 구간만 표시). 3개 미만 구간은 평균 자신감 막대는 그대로 두고, 적중률 막대와 적중률 수치 자리에 `기록 부족`과 기록 수(예: "기록 부족 · 1개")를 보여 준다. 판정도 하지 않는다. Reality Check와 같은 "적으면 적중률을 보여 주지 않는다" 원칙이다(학습자 결정).
**차이 표시:** 요약의 "평균 자신감과 적중률의 차이"와 구간별 차이는 **화면에 표시된 반올림 숫자끼리 뺀 값**으로 보여 준다(예: 82% − 56% → 26%p). 과신/과소확신/비슷함 판정은 반올림 전 값으로 한다(학습자 결정). 결과 기록 완료가 0개면 요약과 그래프 대신 "아직 결과 기록이 없어요"를 보여 준다. 샘플이 포함되면 `샘플 데이터 포함`을 표시한다. 탭을 열 때마다 새로 계산하므로 결과 저장·수정이 바로 반영된다.
PRD ref: `prd.md > Insights`.

## Data Model

localStorage 키 `decision-journal.v1`에 저장되는 내용:

```json
{
  "version": 1,
  "decisions": [
    {
      "id": "d_1729650000000_ab12",
      "isSample": true,
      "createdAt": "2026-09-12",
      "title": "중고 자전거 대신 새 자전거 사기",
      "expected": "출퇴근을 주 3회 이상 자전거로 하게 된다",
      "reasoning": "새 자전거면 고장 걱정이 적다",
      "area": "money",
      "mood": "confident",
      "confidence": 85,
      "reviewInterval": "1m",
      "review": {
        "happened": "주 2회 정도 탔다",
        "accuracy": "partly",
        "outcome": "good",
        "reviewedAt": "2026-10-15",
        "editedAt": null
      }
    }
  ]
}
```

- **분야 코드:** `money`, `career`, `health`, `relationships`, `home`, `other`. 화면 이름은 strings.js에서 돈 / 커리어 / 건강 / 관계 / 집 / 기타로 나온다.
- **기분 코드:** `calm`, `confident`, `excited`, `anxious`, `rushed`, `tired`. 화면 이름은 평온 / 자신감 / 들뜸 / 불안 / 서두름 / 피곤함.
- **검토 기간:** `1w` = 7일, `1m` = 30일, `3m` = 90일. 1개월을 30일로 단순화했다.
- **날짜:** 시간 없이 사용자 기기 기준 `YYYY-MM-DD`로 저장하고 비교한다. 검토 예정일 = 기록 날짜 + 검토 기간. 오늘 ≥ 검토 예정일이고 결과가 없으면 `검토할 때 됨`이다.
- **잠금:** 예측 쪽 필드(제목~검토 기간, 기록 날짜)는 `addDecision` 때 한 번만 쓰인다. 이후에는 `saveReview`가 `review`만 바꾼다.
- **떠났다 돌아오면:** 모든 기록과 결과가 localStorage에 남아 있어 그대로 보인다. 필터 선택과 작성 중이던 폼 내용은 남지 않는다.

## Sample Data Plan
PRD ref: `prd.md > Product Decisions` (데모용 샘플 구성).

10개 모두 가상이다. "N일 전"은 처음 열거나 초기화한 날 기준이다.

| # | 결정 (요약) | 분야 | 기분 | 자신감 | 기간 | 기록 | 적중 | 결과 평가 |
|---|---|---|---|---|---|---|---|---|
| 1 | 이직 제안 수락 | 커리어 | 들뜸 | 80 | 3개월 | 120일 전 | 맞음 | 좋음 |
| 2 | 헬스장 연간 회원권 | 건강 | 자신감 | 82 | 1개월 | 75일 전 | 틀림 | 나쁨 |
| 3 | 적금 해지하고 노트북 구입 | 돈 | 서두름 | 85 | 1개월 | 60일 전 | 맞음 | 반반 |
| 4 | 이사 대신 재계약 | 집 | 평온 | 88 | 1개월 | 50일 전 | 틀림 | 좋음 |
| 5 | 친구 모임 주최 | 관계 | 들뜸 | 70 | 1주 | 40일 전 | 맞음 | 좋음 |
| 6 | 주말 부업 시작 | 커리어 | 불안 | 75 | 1개월 | 70일 전 | 맞음 | 반반 |
| 7 | 아침 운동 습관 들이기 | 건강 | 평온 | 78 | 1개월 | 45일 전 | 일부 맞음 | 좋음 |
| 8 | 중고차 구매 | 돈 | 자신감 | 95 | 1개월 | 90일 전 | 틀림 | 반반 |
| 9 | 온라인 강의 등록 | 기타 | 피곤함 | 85 | 1주 | 10일 전 | (결과 없음) | — |
| 10 | 가족 여행 일정 변경 | 관계 | 불안 | 55 | 1개월 | 3일 전 | (결과 없음) | — |

이렇게 만들면 데모에서 보이는 것:
- **경고 (80–89% 구간):** 결과가 기록된 #1–4, 4개. 적중률 (1+0+1+0)/4 = **50%**. 슬라이더 80 → 차이 30%p → 경고.
- **비슷해요 (70–79% 구간):** #5–7, 3개. 적중률 (1+1+0.5)/3 = **83.3%**. 슬라이더 75 → 차이 8.3%p → "비슷해요". 일부 맞음 0.5점도 여기서 보인다.
- **기록 부족 (90–100% 구간):** #8, 1개 → "비교할 기록이 부족해요. 현재 1개예요". 50–59% 구간은 0개.
- **검토할 때 됨:** #9 (1주 기간, 10일 전 기록). 데모에서 이 기록에 **맞음**을 기록하면 80–89% 구간이 **5개, (1+0+1+0+1)/5 = 60%**가 된다. 학습자가 PRD 대화에서 든 예시 문장과 같은 숫자다.
- **검토 예정:** #10 (1개월 기간, 3일 전 기록).
- **맞음 ≠ 좋음:** #4는 틀렸지만 좋았고, #3은 맞았지만 반반이었다. 둘이 따로라는 점이 목록과 상세에서 보인다.
- **초기 Insights:** 완료 8개, 전체 적중률 4.5/8 = 56.25% → 화면 56%, 평균 자신감 653/8 = 81.625% → 화면 82%, 차이 화면 표시 82 − 56 = **26%p**.
- **초기 Insights 구간별:** 80–89% 4개(평균 자신감 84%, 적중률 50%, 과신) · 70–79% 3개(평균 74%, 적중률 83%, 비슷함) · 90–100% 1개(평균 95%, 기록 부족 · 1개). #9에 맞음을 기록하면 80–89%가 5개(평균 84%, 적중률 60%, 과신)가 된다.

## Testing

### Calculation tests (`tests/calc.test.js`, `npm test`)
- 구간: 80 → 80, 89 → 80, 90 → 90, 100 → 90.
- 적중률: 맞음·일부 맞음·틀림 조합. 결과 평가(좋음/반반/나쁨)를 바꿔도 적중률은 그대로. 결과 없는 기록은 제외.
- Reality Check: 2개 → insufficient. 3개 + 차이 정확히 15 → warning. 3개 + 차이 14.9 → similar. 샘플 포함 여부 표시.
- Insights: 0개면 "없음". 샘플 데이터 기준 초기 요약값(8개, 56.25, 81.625), 화면 차이 26(82 − 56), 구간별 판정. 3개 미만 구간은 적중률 대신 기록 부족.
- 차이 표시와 판정 분리: 화면 차이 = 반올림한 숫자끼리의 차이. 80 vs 65.4는 화면 차이 15지만 판정은 비슷함(반올림 전 14.6).
- 상태: 검토 예정일 하루 전 / 당일 / 결과 있음.
- 샘플 데이터: 위 Sample Data Plan의 구간별 개수와 적중률이 실제로 나오는지.

### Browser tests (`tests/e2e.test.js`, `npm run test:e2e`)
테스트용 로컬 서버로 앱을 열고 Chromium으로 실제 조작한다. 테스트마다 새 브라우저 저장 공간에서 시작한다.
1. **새로고침 후 기록 유지:** 새 결정을 저장 → 새로고침 → 목록에 그대로 있고 상세 내용이 같다.
2. **새로고침 후 결과 유지:** #9에 결과 기록 → 새로고침 → `결과 기록 완료` 상태와 결과 내용이 남아 있다. 결과 수정 → 새로고침 → 수정 내용이 남아 있다.
3. **잠금:** 저장된 기록의 상세 화면에 예측 쪽 입력란과 편집 버튼이 없다(결과 수정 중에도).
4. **Reality Check 실시간 갱신:** 슬라이더 80 → 경고와 "4개 · 50%". 75 → "비슷해요". 95 → 부족 문구.
5. **결과가 Insights에 반영:** #9에 맞음 기록 → Insights의 80–89% 구간이 5개, 60%.
6. **초기화 확인창:** 취소 → 직접 만든 기록이 남는다. 확인 → 샘플 10개만 남는다.

## Suggested Build Order
`5-build`가 실제 단계와 체크리스트를 만든다. 아래는 이 설계가 권하는 순서다. 핵심(Reality Check)을 일찍 화면에 올리고, 각 단계가 끝날 때마다 앱이 열리는 상태를 유지한다.

1. **뼈대와 미리보기 확인** — `index.html`, `styles.css` 색 변수, `strings.js`, 공통 상단, `#` 화면 이동. 비공개 Artifact로 올려 링크가 열리고 localStorage가 새로고침 후에도 유지되는지 학습자가 직접 확인한다.
2. **계산과 샘플** — `calc.js`, `sample-data.js`, `tests/calc.test.js`. 화면 없이 `npm test`로 구간·적중률·15%p 경계·샘플 숫자를 확인한다.
3. **저장** — `storage.js`(불러오기, 처음엔 샘플 저장, 잠금 규칙, 초기화, 저장 불가·데이터 깨짐 대응).
4. **Journal 목록** — 카드, 상태 3종, 샘플 표시, 상태·분야 필터, 빈 결과 안내, `샘플로 초기화` 확인창.
5. **새 결정 폼 + Reality Check** — 폼, 필수 항목 안내, 슬라이더 실시간 패널(경고 / 비슷해요 / 부족). 저장 후 목록에 반영.
6. **상세와 결과 검토** — 잠긴 예측 표시, 결과 기록, `결과 수정`, 취소.
7. **Insights** — 요약 4개(화면 차이 방식), 구간 막대그래프, 기록 부족 표시, 0개 안내.
8. **브라우저 테스트와 마무리** — `package.json`, `tests/e2e.test.js`, `static-server.js`. 6개 시나리오를 통과시키고, 좁은 화면 배치를 확인하고, README를 쓴다. 최종 Artifact로 데모 경로 1–7을 학습자가 직접 시연한다.

## External Services and Dependencies

외부 서비스, API, 데이터베이스, 키가 없다. 앱 실행에는 브라우저만 있으면 된다.
개발용으로만 Playwright `1.56.1`을 쓴다(무료). 이 컨테이너에는 Chromium이 미리 설치돼 있으므로 브라우저를 따로 내려받지 않는다.

## Important Failure Modes

- **localStorage를 쓸 수 없음** (사생활 보호 모드, 미리보기 환경, 저장 차단) → 메모리에서만 동작하고, 상단에 "이 환경에서는 저장되지 않아요. 새로고침하면 처음 샘플로 돌아가요"를 표시한다. 저장 시도는 모두 실패해도 앱이 멈추지 않게 감싼다.
- **저장된 데이터가 깨졌거나 형식이 다름** → 저장된 데이터를 자동으로 덮어쓰지 않는다. 샘플을 메모리로 보여 주고 "저장된 기록을 읽을 수 없어요. 샘플로 초기화하면 다시 시작할 수 있어요"를 표시한다.
- **날짜 경계 오류** (시간대 때문에 검토할 때 됨이 하루 어긋남) → 날짜를 시간 없이 기기 기준 `YYYY-MM-DD`로만 다루고, 계산 테스트에서 예정일 하루 전 / 당일을 확인한다.

## What Was Simplified and Why

- **1개월 = 30일** (달력상 한 달 대신) — 계산이 단순하고 데모에 차이가 없다. 달력 기준으로 하려면 월말 처리 규칙이 더 필요하다.
- **브라우저 기본 확인창**(`confirm`)으로 초기화 확인 — 직접 만든 대화상자 대신. PRD 문구와 취소/확인 동작을 그대로 지킨다. 나중에 디자인을 맞추려면 자체 대화상자로 바꾸면 된다.
- **CSS 막대그래프** (차트 도구 대신) — 인터넷 없이 보이고 차분한 디자인을 맞추기 쉽다. 그래프 종류를 늘리려면 차트 도구를 들일 수 있다.
- **매 저장마다 전체 데이터 다시 쓰기** — 기록 수십 개 규모에서는 충분하다.
- **샘플 날짜는 상대값으로 생성** — 언제 열어도 #9가 `검토할 때 됨`이 되게 하기 위해서다. 고정 날짜를 쓰면 시간이 지나 상태가 어긋난다.

## Decisions and Open Issues

**학습자 결정:**
- 순수 HTML·CSS·JavaScript, 프레임워크·빌드 없음 — 기능 작동이 우선이라서. 감수: 화면 갱신을 직접 챙긴다.
- 한국어 화면 문구는 한 파일(`js/strings.js`)에 모은다.
- 저장은 localStorage.
- Claude Code 웹에서 미리보고 시연할 방법을 계획에 포함한다.
- 새로고침 후 기록 유지 테스트를 넣는다.

**이 결정에서 따라 나온 구현 세부 (리뷰에서 바꿀 수 있음):**
- 미리보기는 비공개 Artifact 링크로 하고, 확인용으로 컨테이너 Chromium 스크린샷을 쓴다.
- 자동 테스트는 Node 내장 테스트(계산)와 Playwright(브라우저)로 한다. Playwright는 개발용이라 `package.json`과 `node_modules`가 생기지만, 앱 실행에는 영향이 없다.
- 일반 `<script>` 태그와 `window.DJ` 공용 보관함을 쓴다. 더블클릭 실행을 지키기 위해서다.
- 주소 `#`로 화면을 이동해, 새로고침해도 같은 화면이 유지된다.
- 슬라이더 시작값 50, 1 단위.
- **학습자 결정:** 화면의 차이는 표시된 숫자끼리 빼서 보여 주고, 경고·판정은 반올림 전 값으로 계산한다.
- 그래프에는 결과 기록이 있는 구간만 표시한다(PRD Open Question 해결 제안).
- **학습자 결정:** 3개 미만 구간은 Insights 그래프에서 적중률 막대와 수치 대신 `기록 부족`과 기록 수를 보여 준다.
- **학습자 결정:** 테스트용 `package.json`과 Playwright 추가를 허용한다.
- 샘플 10개는 위 Sample Data Plan대로 구성한다(PRD Open Question 해결).

**학습자의 불확실했던 점:** "Claude Code 웹에서 작업 중인데, 더블클릭 말고 이 환경에서 앱을 어떻게 미리보고 시연하나?"
- 해결: 컨테이너 안 주소는 학습자 브라우저에서 열 수 없으므로, 비공개 Artifact 링크로 직접 조작하고 녹화한다.
- 빌드 중 확인할 것: **빌드 첫 단계에서** 최소 화면을 Artifact로 올려 (1) 링크가 열리는지, (2) 기록이 Artifact에서 새로고침 후에도 남는지 학습자가 직접 확인한다. 남지 않으면 실패 대응(메모리 모드 안내)이 보이는지 확인하고, 시연 경로를 내려받은 `index.html` 또는 GitHub Pages로 바꾼다.

**남은 문제:** 없음. 승인을 막는 문제는 없다.
