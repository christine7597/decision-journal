# Decision Journal — Product Requirements

결정하기 전에 예상 결과와 자신감을 기록해 잠그고, 나중에 실제 결과를 기록해 자신감과 실제 적중률을 비교하는 개인용 결정 일지. 사용자는 학습자 본인이며, 데모는 가상의 샘플 데이터로만 진행한다.
Source: `scope.md > The Unique Kernel`, `scope.md > Who It's For`.

## The Core Journey
Source: `scope.md > What "Working" Looks Like`, `scope.md > The Core Loop`.

1. 앱을 열면 **Journal 목록** 화면이 보인다. 상단에 "샘플 데이터" 안내가 분명하게 표시되어 있다.
2. **New decision** 버튼을 눌러 새 결정 입력 화면으로 간다.
3. 결정, 예상 결과, (선택) 이유, 분야, 기분, 자신감, 검토 기간을 입력한다.
4. 자신감 슬라이더를 움직이면 오른쪽 **Reality Check** 패널이 즉시 갱신되어, 같은 자신감 구간의 과거 적중률과 비교해 보여 준다.
5. 저장하면 Journal 목록으로 돌아가고 새 기록이 나타난다. 기록을 열면 예측 내용이 **잠겨 있어** 수정할 수 없다.
6. **검토할 때 됨** 상태인 샘플 기록을 열어, 실제로 일어난 일을 적고 예측 적중(맞음 / 일부 맞음 / 틀림)과 결과의 좋고 나쁨(좋음 / 반반 / 나쁨)을 **따로** 기록한다.
7. **Insights** 탭으로 가면, 방금 기록한 결과가 해당 구간의 기록 수와 적중률에 반영되어 있다.

성공 기준: 위 1–7을 약 1분 안에 화면에서 끊김 없이 보여 줄 수 있다.

## Screens and Layout

- **공통 상단:** 앱 이름, Journal / Insights 탭, 눈에 잘 띄는 New decision 버튼, 항상 보이는 샘플 데이터 안내.
- **Journal 목록** (첫 화면): 필터와 기록 카드 목록, `샘플로 초기화` 버튼.
- **새 결정 입력 화면:** 왼쪽에 입력 폼, 오른쪽에 Reality Check 패널.
- **기록 상세 / 결과 검토 화면:** 잠긴 예측 내용과 결과 검토 영역.
- **Insights 화면:** 상단 요약 수치, 그 아래 자신감 구간별 그래프.

이동: 기록 카드 → 상세/결과 검토, New decision → 입력 화면, Insights 탭 → 분석 화면, Journal 탭 → 목록.

## Look and Feel

- 차분한 **기록장** 느낌. 화려한 효과나 복잡한 대시보드는 쓰지 않고, 기록과 비교에 집중하게 한다.
- 오프화이트 또는 연한 회색 배경, 둥근 흰색 카드, 짙은 글자색.
- 경고에만 **절제된 빨간색** 포인트.
- Insights의 숫자와 그래프는 크고 읽기 쉽게.
- 화면 문구는 **한국어**. 제출 전에 영어로 바꿀 예정이므로 모든 화면 문구(버튼, 탭, 안내, 상태명, 메시지)를 **한곳에서 관리**해, 그곳만 고치면 언어가 바뀌게 한다.

## Features and Behavior

### Journal List
Source: `scope.md > The POC Boundary`.

각 기록 카드에 표시: 결정 제목, 분야, 당시 기분, 기록 날짜, 자신감 %, 현재 상태. 샘플 기록에는 `샘플` 표시가 붙는다.

상태는 세 가지:
- **검토 예정:** 결과가 없고, 기록 날짜 + 검토 기간이 아직 지나지 않음.
- **검토할 때 됨:** 결과가 없고, 검토 기간이 지남.
- **결과 기록 완료:** 결과가 기록됨.

필터: 상태 필터(전체 / 미해결 / 완료)와 분야 필터(전체 + Money, Career, Health, Relationships, Home, Other의 한국어 표기). "미해결"은 검토 예정과 검토할 때 됨을 함께 포함한다. 두 필터는 함께 적용된다.

- [ ] 첫 화면이 Journal 목록이고, 샘플 데이터 안내가 상단에 보인다.
- [ ] 카드마다 제목, 분야, 기분, 기록 날짜, 자신감 %, 상태가 보이고, 샘플 기록에만 `샘플` 표시가 있다.
- [ ] 세 가지 상태가 날짜와 결과 유무에 따라 올바르게 표시된다.
- [ ] 상태 필터와 분야 필터를 조합하면 조건에 맞는 기록만 남는다.
- [ ] 필터 결과가 없으면 빈 목록 대신 해당 조건의 기록이 없다는 안내가 보인다.

### New Decision Form
Source: `scope.md > The POC Boundary`.

입력 항목: 결정, 예상 결과, 이유(선택), 분야(6개 중 하나), 기분(평온 / 자신감 / 들뜸 / 불안 / 서두름 / 피곤함 — Calm, Confident, Excited, Anxious, Rushed, Tired), 자신감(슬라이더, %), 검토 기간(1주 / 1개월 / 3개월).

- [ ] 이유를 제외한 항목이 비어 있으면 저장되지 않고, 어떤 항목이 필요한지 안내한다.
- [ ] 저장하면 Journal 목록에 새 기록이 `검토 예정` 상태로, `샘플` 표시 없이 나타난다.

### Reality Check
Source: `scope.md > The Unique Kernel`.

새 결정 입력 화면 오른쪽에 표시되며, 자신감 슬라이더를 움직이는 즉시 갱신된다. **자신감 값을 자동으로 바꾸지 않는다.**

규칙:
- **비교 대상:** 현재 자신감과 같은 10% 구간(예: 80% → 80–89%)에 속하고 **결과 기록이 완료된** 과거 기록. 결과가 없는 기록은 제외한다.
- **적중률:** (맞음 1점 + 일부 맞음 0.5점 + 틀림 0점의 합계) ÷ 결과 기록 완료 기록 수 × 100. 결과가 좋았는지(좋음/반반/나쁨)는 계산에 넣지 않는다.
- **비교 기록 3개 미만:** "비교할 기록이 부족해요. 현재 N개예요"만 표시한다. 적중률 수치는 보여 주지 않는다.
- **3개 이상이고 |자신감 − 적중률| ≥ 15%p:** 경고(절제된 빨간색). 예: "현재 자신감은 80%지만, 과거 비슷한 자신감으로 예상한 기록 5개의 실제 적중률은 60%였어요". 정확히 15%p도 경고한다.
- **3개 이상이고 차이 < 15%p:** 경고 없이 "현재 자신감이 과거 기록과 비슷해요".
- **항상 표시:** 비교 기록 수, 그리고 비교 자료에 샘플이 포함되어 있으면 `샘플 데이터 포함` 안내. 3개 이상일 때는 현재 자신감과 과거 적중률도 함께 표시한다.
- 3개와 15%p는 첫 버전의 동작 기준이며, 통계적 신뢰성을 보장하는 기준이 아니다.

- [ ] 슬라이더를 움직이면 페이지 이동 없이 패널이 즉시 바뀐다.
- [ ] 비교 기록이 3개 미만인 구간에서는 부족 문구와 현재 개수만 보이고, 적중률 숫자는 보이지 않는다.
- [ ] 샘플 데이터로 경고가 뜨는 구간에서 문구와 숫자가 위 공식대로 계산된다(손으로 검산 가능).
- [ ] 차이가 정확히 15%p인 경우 경고가 뜬다.
- [ ] 차이가 15%p 미만이면 "비슷해요" 문구와 네 가지 정보가 보인다.
- [ ] 자신감 값은 사용자가 움직이기 전에는 바뀌지 않는다.

### Locked Prediction and Outcome Review
Source: `scope.md > The Unique Kernel`, `scope.md > The POC Boundary`.

기록을 열면 상세 화면이 보인다. 저장 시점의 결정, 예상 결과, 이유, 분야, 기분, 자신감, 검토 기간, 기록 날짜가 **읽기 전용**으로 표시되고, 수정 수단이 없다. 잠겨 있다는 것이 화면에 명시된다.

결과가 없는 기록에는 결과 검토 영역이 있다: 실제로 일어난 일(텍스트), 예측 적중(맞음 / 일부 맞음 / 틀림), 결과 평가(좋음 / 반반 / 나쁨). 두 평가는 서로 다른 질문으로 나뉘어 보인다.

**잠금과 수정의 경계:** 잠기는 것은 최초 예측 내용(결정, 예상 결과, 이유, 검토 기간, 기록 날짜)과 당시 자신감·기분·분야다. 나중에 입력하는 결과 세 항목(실제로 일어난 일, 예측 적중, 결과 평가)은 저장 후에도 **수정할 수 있다**. 결과가 기록된 상세 화면에는 `결과 수정` 버튼이 있고, 누르면 기존 결과가 채워진 상태로 편집할 수 있다. 저장하면 수정된 결과로 바뀌고, 취소하면 기존 결과가 그대로 남는다. 결과를 수정해도 최초 예측은 그대로이며, Reality Check와 Insights는 수정된 결과로 다시 계산된다. 오타 하나를 고치려고 전체 데이터를 초기화할 필요가 없어야 한다.

- [ ] 저장된 예측 내용과 당시 자신감·기분·분야를 바꿀 수 있는 입력란이나 편집 버튼이 없다(결과를 기록하기 전에도, 수정하는 중에도).
- [ ] 결과 세 항목을 모두 입력해야 저장된다(처음 기록할 때와 수정할 때 모두).
- [ ] 결과를 저장하면 상태가 `결과 기록 완료`로 바뀌고, 이후 Reality Check 비교 자료와 Insights 계산에 포함된다.
- [ ] 결과가 기록된 기록에서 `결과 수정`으로 세 항목을 바꿔 저장하면, 상세 화면에 수정된 결과가 보이고 최초 예측은 그대로다.
- [ ] 예측 적중을 바꿔 저장하면(예: 맞음 → 틀림) Reality Check와 Insights의 해당 구간 적중률이 수정된 값으로 다시 계산된다. 기록 수는 늘지 않는다.
- [ ] 결과 평가(좋음/반반/나쁨)만 바꾸면 적중률은 바뀌지 않는다.
- [ ] 수정 중 취소하면 기존 결과가 그대로 남는다.
- [ ] 수정한 결과는 새로고침 후에도 유지된다.

### Insights
Source: `scope.md > The POC Boundary`.

대상은 **결과 기록이 완료된 기록만**이다.

상단 요약: 완료된 기록 수, 전체 적중률, 평균 자신감(같은 완료 기록 기준), 평균 자신감과 적중률의 차이.

그 아래: 자신감 구간별로 평균 자신감과 실제 적중률을 나란히 비교하는 그래프. 구간마다 비교 기록 수를 표시한다. 3개 미만인 구간은 `기록 부족`으로 표시하고 과신·과소확신을 판정하지 않는다.

결과를 저장하거나 수정하면 즉시 다시 계산된다. 예측 적중과 결과의 좋고 나쁨은 섞지 않는다. 샘플 데이터 안내는 항상 보인다.

- [ ] 요약 네 수치가 완료 기록만으로 계산된다(손으로 검산 가능).
- [ ] 구간마다 기록 수가 보이고, 3개 미만 구간은 `기록 부족`으로 표시되며 판정이 없다.
- [ ] 결과를 하나 기록한 뒤 Insights에 가면 해당 구간의 기록 수와 적중률이 바뀌어 있다.
- [ ] 기존 결과의 예측 적중을 수정한 뒤 Insights에 가면 기록 수는 그대로이고 적중률만 수정된 값으로 바뀌어 있다.
- [ ] 완료 기록이 하나도 없으면 0%가 아니라 "아직 결과 기록이 없어요"가 보인다.

### Sample Data and Reset
Source: `scope.md > The POC Boundary`, `scope.md > Explicitly Cut`.

처음 열면 8–10개의 가상 샘플 기록이 들어 있다. 학습자의 개인 정보는 포함하지 않는다. 직접 저장한 기록은 같은 목록에 보이고, 샘플에만 `샘플` 표시가 붙는다.

`샘플로 초기화` 버튼을 누르면 즉시 지우지 않고 "직접 추가한 기록과 검토 결과가 삭제되고 처음 샘플 상태로 돌아갑니다. 계속할까요?"라고 확인한다.

- [ ] 취소하면 아무것도 바뀌지 않는다.
- [ ] 확인하면 이 앱의 저장 데이터만 처음 샘플 상태로 돌아간다(직접 추가한 기록과 샘플에 기록한 결과 모두 사라짐).

## States and Boundaries

- **첫 사용:** 샘플 기록 8–10개가 보이고, 샘플 데이터 안내가 표시된다.
- **저장 유지:** 기록과 검토 결과는 브라우저에 저장되어 새로고침하거나 다시 열어도 남는다.
- **결과 없는 새 기록:** Reality Check 비교 자료와 Insights 적중률 계산에서 제외된다.
- **결과 수정:** 최초 예측은 바뀌지 않고, 계산은 수정된 결과 기준으로 다시 이루어진다.
- **비교 자료 부족:** Reality Check는 부족 문구와 개수만, Insights 구간은 `기록 부족`만 표시한다. 수치를 지어내지 않는다.
- **완료 기록 0개:** Insights에 "아직 결과 기록이 없어요".
- **필터 결과 없음:** 조건에 맞는 기록이 없다는 안내.
- **입력 누락:** 필수 항목이 비면 저장하지 않고 안내한다.
- **초기화 취소:** 아무 변화 없음.

## Product Decisions

- **10% 구간 비교** — "비슷한 자신감"을 단순하고 설명 가능하게 정의.
- **일부 맞음 = 0.5점** — 부분 적중을 전부 맞음이나 틀림으로 왜곡하지 않기 위해.
- **적중과 결과 평가를 분리** — 맞는 것과 좋은 결과는 다르다는 핵심 아이디어를 지키기 위해.
- **3개 / 15%p 기준, 정확히 15%p면 경고** — 첫 버전의 동작 기준일 뿐 통계적 신뢰성 보장이 아님을 명시.
- **자신감을 자동으로 바꾸지 않음** — 판단은 사용자가 한다.
- **기록 0개일 때 0% 대신 안내 문구** — 0%는 "전부 틀림"으로 오해되기 때문.
- **결과 없는 새 기록은 계산 제외** — 아직 알 수 없는 결과로 통계를 오염시키지 않기 위해.
- **샘플 표시와 `샘플 데이터 포함` 안내** — 샘플 통계를 실제 기록으로 오해하지 않게.
- **예측은 잠그고 결과는 수정 가능** — hindsight로 바꾸면 안 되는 것은 최초 예측과 당시 자신감·기분·분야다. 나중에 쓰는 결과는 오타나 판단 정정을 위해 고칠 수 있어야 하며, 오타 하나 때문에 전체 데이터를 초기화하게 만들지 않는다.
- **확인을 거치는 초기화** — 실수로 기록을 잃지 않게.
- **한국어 화면, 문구는 한곳에서 관리** — 제출 전에 영어로 쉽게 바꾸기 위해. 언어 전환 기능은 만들지 않음.
- **기분·분야별 분석 제외** — 샘플 8–10개를 6개 그룹으로 나누면 그룹당 1–2개뿐이라 의미 없는 통계가 되기 때문.

**리뷰에서 확정된 결정 (이전 가정 A1–A6):**
- **100%는 90–100% 구간에 포함.**
- **데모용 샘플 구성:** 경고, "비슷해요", `기록 부족` 상태와 `검토할 때 됨` 기록을 모두 시연할 수 있게 구성한다. 샘플의 기록 날짜는 앱을 연 날짜 기준 과거로 잡아, 언제 열어도 상태가 맞게 보이게 한다. 샘플별 구체적인 숫자는 `4-spec`에서 정한다.
- **Insights 구간 판정은 Reality Check와 같은 기준:** 3개 이상이고 차이 15%p 이상이면 과신/과소확신 판정, 미만이면 "비슷함", 3개 미만이면 `기록 부족`.
- **결과는 검토 예정일 전에도 기록할 수 있다.** 상태 표시는 날짜를 따르되 기록을 막지 않는다.
- **결과는 수정 가능, 예측은 잠금** (위 결정 참고; 이전 A5를 대체).
- **앱 이름은 Decision Journal.**

## What We're Building

- Journal 목록 + 상태/분야 필터 + 샘플 표시
- 새 결정 입력 폼 + 실시간 Reality Check
- 저장 후 예측 잠금(최초 예측과 당시 자신감·기분·분야)
- 상세 화면 + 결과 검토(적중과 결과 평가 분리) + 결과 수정
- Insights 요약 수치 + 구간별 그래프
- 8–10개 가상 샘플 데이터, 브라우저 저장, 확인을 거치는 `샘플로 초기화`
- 한곳에서 관리하는 한국어 화면 문구

## Deferred From the POC

- **기분·분야별 세부 분석** — 샘플이 적어 그룹별 통계가 의미 없음(`scope.md > Later`).
- **개별 기록 삭제** — 데모에 필요 없음. 지금은 초기화로 대신한다. (예측 수정은 잠금 원칙상 하지 않으며, 결과 수정은 이번 버전에 포함.)
- **한국어/영어 전환 기능** — 제출 전 한 번 바꾸면 충분함.

## Possible Later Enhancements

- 기분·분야별 패턴 분석(데이터가 충분히 쌓인 뒤).
- 검토 기간이 된 기록 알림.
- 데이터 내보내기/가져오기(백업).

## Non-Goals

- 로그인, 계정, 동기화, 서버 — 1인용 일지에는 브라우저 저장으로 충분(`scope.md > Explicitly Cut`).
- 실제 개인 데이터로 데모 — 공개 저장소와 영상에는 가상 기록만 사용.
- 통계적 유의성 검정 — 첫 버전 기준은 동작 기준일 뿐.
- 자신감 자동 보정이나 조언 — 앱은 비교만 보여 주고 판단은 사용자가 한다.

## Open Questions

- 샘플별 구체적인 숫자(자신감, 적중 결과, 날짜) — `4-spec`에서 정함.
- 그래프에 기록이 전혀 없는 구간까지 모두 표시할지, 기록이 있는 구간만 표시할지 — 빌드 중에 정해도 됨.
